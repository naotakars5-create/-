# 旅費精算書 入力アプリ（プロトタイプ）

社員が Web 画面から出張の内容を入力すると、既存の Excel 様式「旅費精算書」に
自動で値を書き込み、ダウンロードできる Web アプリの試作。

> 当初は音声入力 + AI抽出（Web Speech API + OpenAI）で作っていたが、
> 「音声入力はやめて、PC で直接入力 → 履歴から選んで日付だけ変える」という
> 運用に変更したいとの要望を受け、音声・AI 関連機能は削除した
> （詳細は下記「経緯」を参照）。

## 技術スタック

- Next.js (App Router) + TypeScript
- 入力: Web 画面のフォームに直接入力（手入力）
- 履歴: 過去に登録した出張パターンを `localStorage` に保存し、次回はワンクリックで
  呼び出して日付だけ変更すればよい
- Excel 書き込み: Node の `exceljs`（数式・書式・結合セルを壊さず、指定セルに値のみ書き込み）
- PC / スマホ両対応のレスポンシブ

## セットアップ

```bash
npm install
npm run dev   # http://localhost:3000
```

環境変数は現在必須のものはない（`.env.example` 参照。Google Maps 連携は任意・現状未使用）。

## 開発の進め方（仕様どおりの順序）

1. **Excel 書き込みを CLI で確立**（UI より先）

   ```bash
   npm run template     # templates/template.xlsx を生成（数式・結合セル込み）
   npm run test:write   # サンプル出張を書き込み output/sample.xlsx を生成
   npm run test:verify  # 数式・結合セル・入力値を自動検証
   ```

   `output/sample.xlsx` を Excel で開き、体裁・数式が崩れていないことを確認できる。

2. **Web UI をかぶせる**（設定 → 入力 → 一覧 → 出力）

## 様式の実装メモ

- 1 シート = 半月分。シート名 `YYYY_M_1`（前半 1〜15 日）/ `YYYY_M_2`（後半 16〜31 日）
- 1 件 = 5 行ブロック（開始行 6, 11, 16, 21, 26, 31、最大 6 件/シート）
- 数式セル・結合セルの非アンカー・固定ラベル（`B6="/"` など）には**書き込まない**
- 既存ファイルで欠落していた `H25 = SUM(H21:H24)` はテンプレ生成時に補完済み
- 金額は整数、日当は役職から自動決定
- `template.ts` のセル配置・結合セル・固定文言（会社名等）は、実際に使われている
  過去分 .xls（2025年7月〜2026年6月、25シート）を Python (`xlrd`) で解析して実測した
  ものと**結合セル95件すべてが完全一致**することを確認済み

### 分離された差し替えポイント（将来対応）

- `getFare(from, to, roundTrip)` … 運賃マスタ（`src/lib/fareMaster.json`）。
  現状の UI からは呼び出していないが、コードは残してある。
- `shouldPayAllowance(trip)` … 日当支給条件。現状は常に false（UI トグル）。ルール確定後に自動判定へ

## テンプレート .xlsx について

実際に使われている既存テンプレ `.xls` の内容を実測し、`src/lib/excel/template.ts` が
コードで再現している（Vercel のサーバレス環境では LibreOffice 等のバイナリ変換ツールが
使えないため、実ファイルをそのまま同梱するのではなく、構造をコードに落とし込む方式を採用）。
`npm run template` で `templates/template.xlsx` を生成する。

## 入力フロー

1. 「入力」タブで **「＋ 新しい出張を追加」**、または **「過去に選択した出張から選ぶ」**
   （履歴、後述）で下書きカードを追加する
2. 各項目（月日・出張先・訪問先・用務・経路・運賃・タクシー代・宿泊料・日当 等）を
   画面上で直接入力・修正する。出張先などの入力欄は履歴からのオートコンプリート候補が出る
3. 複数件まとめて用意してから **「すべてリストに追加」** で一括登録できる
4. 「出力」タブで対象月を選び Excel をダウンロード

### 過去の選択内容の再利用

確定した出張は `localStorage`（ブラウザ内のみ、サーバには送らない）に
「行き先・訪問先・用務・経路」等のパターンとして記録される（最大40件、同一パターンは
最新の使用日時で更新）。「入力」タブの「過去に選択した出張から選ぶ」ボタンを押すと、
**今日の日付で**その内容が下書きに追加されるので、日付だけ変更して登録すればよい
（例: 「千葉-稲毛(往復) JR」「旭市 島田建設」のような定型パターンを毎回打ち直さずに済む）。

## 経緯（音声入力・AI抽出の削除について）

初期実装では Web Speech API による音声入力と、OpenAI API (`gpt-4o-mini`) による
テキストからの項目自動抽出、および Google Maps Directions API による運賃自動取得を
実装していた。運用イメージをすり合わせる中で「音声入力はやめて、PC 上で直接入力し、
一度登録した内容は履歴から選んで日付だけ変えれば済むようにしたい」という要望があり、
音声入力・AI抽出機能（`/api/extract`、`useSpeech.ts`、`extractPrompt.ts`、
`openai` パッケージ依存）を削除した。運賃自動取得（`/api/fare`、Google Maps 連携）は
明示的な削除依頼はなかったためコードは残しているが、AI抽出経由でしか呼ばれていなかった
ため、現状の画面からは呼び出されない（将来、手入力フォームに組み込み直すことは可能）。

## プライバシー

個人情報を含むため、プロトタイプ段階ではデータはブラウザ内 state / localStorage のみ。
サーバに保存しない（全社展開フェーズで認証込みで設計する）。
